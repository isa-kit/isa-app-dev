## 2026-08-09 — Three-level map controls (threelvl-0809)

seedVersion `2026-08-09.threelevel`. Adopts the three-level control model on
every map screen. Each screen's overlay `switch` on `map_cards.<screen>.state`
grows a third case, so one column now carries three levels instead of two:

| state | level | what the user sees |
|---|---|---|
| `min` (default) | **L0 chip** | one outlined pill — glyph + short label. Nothing else on the map. |
| `card` | **L1 card** | the pill's box GROWS into a small card: the current view stated in plain language, that screen's one or two most-changed controls, an Edit button, and a collapse back to L0. |
| `edit` | **L2 edit** | the full attribute set for that screen — every control that existed before this round, unchanged. A mode you enter and leave; Done returns to L1. |

Schema: four columns added to `map_cards` (`metric`, `tier`, `month`,
`outlines`). They persist each screen's L1 quick choice, which is what lets the
card STATE the current view rather than merely offer controls — a metric picked
through a `mapSetLayerVisible` chain is otherwise unreadable. One row added
(`best_spots_map`), which previously had a single always-open overlay and now
follows the same three levels. No analytic table changed; `events` remains 41.

Engine: needs flutterboard's `MapOverlayMorph` (`+glmap-overlay-morph.1`) —
without it the L0→L1→L2 transitions are instant swaps rather than one box
growing.
